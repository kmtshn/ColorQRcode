# 6ColorQR

16×16セルと6色を使う、生成・カメラ読み取り用PWAです。画像処理はブラウザー内で完結し、入力や映像を外部へ送信しません。実行時の外部依存はありません。

四隅からの射影変換、RGBの補正、複数候補の本文検証、前回位置の再利用を追加しました。スマートフォン向け画面、PNG保存、レフ板モードを維持しています。

## 使い方

```sh
python -m http.server 8080
```

`http://localhost:8080` を開きます。スマートフォンのカメラ利用にはHTTPSが必要です。四隅と周囲の余白を画面に収め、明るい場所でピントを合わせてください。印刷は5cm角以上が目安です。

スキャンは約200ms間隔で行い、異なる映像フレームで同じ復元内容が2回続いたら表示します。DBGでは推定四隅、分類後のグリッド、マーカー一致数、整合性検査、処理時間、候補数、失敗理由を確認できます。

## 形式と互換性

最大容量はUTF-8で48バイトです。日本語や絵文字は複数バイトを使います。

|生成形式|読み取り|整合性検査|容量|
|---|---|---|---:|
|旧形式|更新後も対応|XORと構造検証|48バイト|
|新形式（標準）|更新後の読み取り側が必要|XOR、CRC-32、構造検証|48バイト|

新形式は長さの予約値で識別し、従来の余白にCRCを追加します。旧アプリは新形式を読み取れません。誤り訂正は実装していません。CRCが失敗した画像を採用せず、次のフレームを待ちます。

旧形式のXORはバイトの入れ替えや相殺を検出できません。連続フレームの一致でも、反射などの持続的な誤りは排除できません。「誤読確率は実質ゼロ」という保証はありません。

## 自動検証

Node.jsとMicrosoft Edgeがある環境で実行できます。

```sh
npm ci
npm test
npm run benchmark:baseline
npm run benchmark:improved
npm run benchmark:v2
npm run results
npm run gallery
```

Chromeの場合は環境変数 `BROWSER_CHANNEL=chrome` を設定してください。ブラウザー起動や依存導入に失敗した試験は未実施であり、成功には数えません。ローカルテストサーバーは `127.0.0.1:8087` を使います。

旧形式の同一画像の復元は124/202件から187/202件へ改善しました。旧形式では反射による誤読が1件残りました。新形式では187/202件を復元し、212件中の誤読は0件でした。この件数から一般環境の誤読確率は推定していません。

正面は新旧とも53/53件、改善版の±5/10/15度の回転は30/30件を復元しました。一方、極端な暗さ、反射、遮蔽、背景接触では失敗が残ります。背景接触の3件は旧版より悪化しました。

すべてWindows上のEdgeによる合成画像試験です。Android Chrome・iOS Safariの実機カメラは未確認です。

## ファイル

|ファイル|役割|
|---|---|
|index.html|画面、生成・復元、カメラ制御|
|scanner.js|フレーム取得、領域検出、射影変換、色分類、追跡、確認状態|
|sw.js / manifest.json|オフラインキャッシュとPWA設定|
|tests/fixtures.js|乱数種を固定した画像生成と変形|
|tests/benchmark.cjs|実ブラウザーによる旧版・新版の測定|
|tests/regression.cjs|整合性、複数候補、フレーム確認、オフラインの回帰テスト|
|tests/baseline/index.html|変更前の原本|
|results/|測定JSON、比較表、画像|

オフラインキャッシュをv4へ更新しました。旧キャッシュからの更新後はページを再読み込みしてください。
