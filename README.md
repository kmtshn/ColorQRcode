# 6ColorQR

> 6色カラーコードの生成とカメラでのリアルタイム読み取りができる、オフライン動作対応のPWAアプリ

スマートフォンのブラウザ（Safari / Chrome）だけで動作し、サーバーや外部ライブラリ不要。
オフィスの蛍光灯下を想定した、シンプルで堅牢な6色カラーコードシステムです。

---

## ✨ 特長

- 📱 **PWA対応** — ホーム画面に追加、オフラインでも起動可能
- 🎨 **6色エンコード** — 白黒QRの約2倍の情報密度（1セル ≈ 2.58 bit）
- 📷 **カメラ自動読み取り** — 中央ガイド枠に合わせるだけで4fpsでデコード
- 💡 **レフ板モード** — スキャン中は背景を真っ白にしてスマホ画面を照明代わりに
- 🪶 **超軽量** — 3ファイル合計 約35KB、外部ライブラリゼロ（Vanilla JS）
- 🔒 **完全ローカル** — サーバー通信なし、データはすべて端末内で処理

## 🎨 6色カラーコード仕様

### 色の割り当て

| 値 | 色 | RGB | HEX | HSV (近似) |
|:-:|:-:|:-:|:-:|:-:|
| 0 | ⬜ 白 | (255, 255, 255) | `#FFFFFF` | V=1.00, S=0.00 |
| 1 | ⬛ 黒 | (0, 0, 0)       | `#000000` | V=0.00, S=0.00 |
| 2 | 🟥 赤 | (225, 29, 72)   | `#E11D48` | H=347°, S=0.87, V=0.88 |
| 3 | 🟨 黄 | (250, 204, 21)  | `#FACC15` | H=48°,  S=0.92, V=0.98 |
| 4 | 🟩 緑 | (22, 163, 74)   | `#16A34A` | H=142°, S=0.87, V=0.64 |
| 5 | 🟦 青 | (37, 99, 235)   | `#2563EB` | H=221°, S=0.84, V=0.92 |

### コード構造

```
24 × 24 = 576セル

┌──────────────────────────┐
│⬛ ……ヘッダー…… ⬜│  ← 上端: バイト長(6進数3桁)
│ │                          │
│ │     データ領域           │
│ │  (1バイト = 4セル)       │
│ │                          │
│🟥 ………………… 🟦│  ← 下端
└──────────────────────────┘
   ↑                       ↑
   キャリブレーション用4隅マーカー
```

| マーカー位置 | 色 | 役割 |
|:-:|:-:|:-:|
| 左上 (0, 0)    | ⬛ 黒 | 明度の暗側基準 |
| 右上 (23, 0)   | ⬜ 白 | 明度の明側基準 |
| 左下 (0, 23)   | 🟥 赤 | 色相基準 + 向き判定 |
| 右下 (23, 23)  | 🟦 青 | 色相基準 + 向き判定 |

### エンコードロジック

1. 入力文字列を **UTF-8 バイト配列** に変換
2. 各バイト (0〜255) を **6進数4桁** に変換
   - 例: `255 → 1103₆` （`1×216 + 1×36 + 0×6 + 3`）
3. 4セル単位で順次マスに書き込み
4. 先頭3セルにバイト長（6進数3桁、最大215）をヘッダーとして埋め込み
5. 4隅マーカーを除いた 572セル のうち、ヘッダー3 + データ`4×N`セルを使用
6. **最大格納容量: 140バイト**（安全マージン込み）

```
1バイト = log₂(256) = 8 bit
4セル   = log₂(6⁴) = 4 × log₂6 ≈ 10.34 bit
→ 効率: 8 / 10.34 ≈ 77% のbit利用率
→ 同サイズの白黒QRより約2倍の容量密度
```

### デコードロジック（HSV判定）

カメラ画像の各セル中央4×4ピクセルを平均化し、以下の順で判定：

```
1. 4隅マーカーから白/黒のV値を取得 → 動的キャリブレーション
2. 明度を [blackV, whiteV] → [0, 1] に正規化（vN）

3. 判定フロー:
   ├─ vN ≥ 0.78 かつ S < 0.30  → ⬜ 白
   ├─ V ≤ 0.18                  → ⬛ 黒（暗部は色相を信用しない）
   ├─ vN ≤ 0.30 かつ S < 0.60   → ⬛ 黒
   ├─ S < 0.18                  → 明度で白/黒
   └─ 色相角度の最近傍:
        H ≈ 350° → 🟥 赤
        H ≈ 48°  → 🟨 黄
        H ≈ 142° → 🟩 緑
        H ≈ 220° → 🟦 青
```

色相判定は**角度距離の最小値**で決まるため、
朱色〜深紅はすべて「赤」、水色〜紺色はすべて「青」として認識されます。

## 🔬 技術詳細

### 使用技術

- **HTML5 Canvas API** — 描画 / ピクセル取得
- **MediaDevices API** — `getUserMedia` でカメラ映像取得
- **TextEncoder / TextDecoder** — UTF-8の変換
- **Service Worker API** — オフラインキャッシュ
- **Web App Manifest** — PWA設定
- **Clipboard API** / **Vibration API** — UX強化

外部ライブラリ・フレームワークは **一切使用していません**。

### スキャンの仕組み

```
┌──────────────────┐
│   <video> (cover) │ ← カメラ映像
│                   │
│   ┌─────────┐    │
│   │ Guide   │    │ ← 中央正方形ガイド枠
│   │         │    │   (画面幅の75%)
│   └─────────┘    │
└──────────────────┘
         ↓ 250msごと（4 fps）
1. ガイド枠領域を video元解像度にマップ
2. <canvas> に 192×192 (24×8) で切り出し描画
3. 24×24セルの中心4×4ピクセルを平均化 → RGBグリッド
4. 4隅マーカー検証 → キャリブレーション
5. HSV判定 → state grid
6. バイト復元 → UTF-8デコード → 表示
```

マーカー検証が失敗したフレームは静かに無視し、次フレームへ進みます。
位置検出アルゴリズムを省略する代わりに、ユーザーが枠合わせするUXで安定性を確保しています。

## 📐 容量設計の根拠

```
全セル数:           24 × 24       = 576
角マーカー:         4セル                 (固定)
ヘッダー:           3セル                 (バイト長 6進数3桁 = 最大215)
データ可用セル:     576 - 4 - 3   = 569
1バイトあたり:      4セル
最大バイト数:       569 / 4       = 142.25 → 140 (安全マージン)
```
